# Work plan for the 2026-11-09 review list

Companion to [CODE-REVIEW-2026-11-09.md](CODE-REVIEW-2026-11-09.md). Item numbers below are
that file's. The plan is six batches run one after the other; inside a batch the agents run
in parallel, each in its own worktree on disjoint files, and a lead session merges, tests,
and commits. Nothing in a later batch is needed by an earlier one.

## Ground rules that shape the plan

- **One `dotnet test` at a time on this machine.** Two at once crash the CLR and report an
  empty green run (memory note). Every agent and the lead run tests as
  `flock /tmp/vst-dotnet-test.lock dotnet test <project> ...`. Builds may run in parallel;
  each worktree has its own `bin/` and `obj/`.
- **Disjoint files per agent.** The batch tables name the files each agent owns. An agent that
  needs a file it does not own stops and reports instead of editing it.
- **Agents do not commit.** They leave the change in their worktree with a short report. The
  lead reads `git -C <worktree> diff`, applies it, runs the full suite serially, and commits
  with `sc`. No git on Saturday; a batch that ends on Saturday is queued with `sc`.
- **Every new or changed check is seen failing once** (CLAUDE.md rule). The agent's report
  names the sabotage it ran.
- **Speech Dispatcher is never tested against the user's own config.** The harness in
  `spike/speechd-s4-install/` and the packer check 3e are the test surfaces. Any local
  install test ends by restoring the AppImage arrangement (memory note).
- **Windows cannot be built here.** Batch 5 edits are verified by CI's Windows job and by a
  manual run on a Windows machine; the plan says so where it applies.

## Agent families and levels

Measured in this session: the five read-only review agents cost 0.29 to 0.46 M tokens each,
2.05 M in total, on Fable. Fix agents read less and write more; the ranges below are
estimates from that measurement, not measurements.

| Kind of work | Family and level | Why | Tokens per agent (estimate) |
| --- | --- | --- | --- |
| String and doc edits, version numbers, shell one-liners | Sonnet 5.5, low (Haiku 5.5 is possible for pure text, but a wrong edit costs more than the saving) | No design; the item says the exact line and the exact text | 0.1 to 0.2 M |
| Shell scripts with sabotage, UI touched-flags, test additions, small C# fixes with existing tests | Sonnet 5.5, medium | Pattern exists in the codebase; the agent copies it | 0.2 to 0.4 M |
| Daemon logic, protocol, concurrency, provider routing, ORT options, SAPI engine | Opus 5.5, high | A wrong fix here is silent for a blind user; needs the reasoning | 0.4 to 0.8 M |
| Redesign with a measurement gate (in-process espeak, voice per script) | Opus 5.5, xhigh | Several files, a decision to measure before building | 0.8 to 1.5 M |
| Review pass over a batch's diff for silent-failure regressions | Fable 5.1 (one agent, read-only, given the diff and not the conclusions) | Highest stakes, lowest token count: it reads a diff, not a tree | 0.2 to 0.4 M |
| Lead session (merge, serial tests, pack, commit) | Opus 5.5 | Judgment without the Fable price; switch with `/model` | 0.15 to 0.3 M per batch |

Fresh agents, never forks: a fork inherits the whole conversation and pays for it on every
turn. The brief below is all a fresh agent needs.

## What makes it token-friendly

- Fresh agents with the brief above, never forks.
- The brief names items and files; agents never re-review and never read whole files.
- One test project per agent, under `flock`; the lead runs the full suite once per batch.
- The packer runs once per batch, by the lead, not by every agent.
- Fable reads diffs, never trees: three to five review passes of 0.2 to 0.4 M each.
- The lead session runs on Opus. Switch with `/model opus` before batch 1 and back when a
  review pass is wanted.
